# pragents UI — UX Audit

**Datum:** 2026-05-14  
**Methode:** Automatisierter UI-Agent (130 Tool-Calls, alle Views durchgegangen)  
**Frontend:** http://localhost:5174 · **Backend:** http://localhost:3000

---

## Zusammenfassung

| Schweregrad | Anzahl |
|---|---|
| 🔴 Blocker | 1 |
| 🟠 Major | 5 |
| 🟡 Minor | 8 |
| 🔵 Nice-to-have | 5 |

**Kritischster Pfad:** TaskDetail-Crash → Chat-Funktionalität defekt → Memory-Suche kaputt.

---

## 🔴 Blocker

### B-1 · `/tasks` — TaskDetail crasht mit JS-Fehler

- **Was:** Klick auf eine Task-Zeile löst App-Crash aus: `TypeError: firstTrace.id?.slice is not a function`
- **Wo:** `TaskDetail`-Komponente, Tasks ohne assoziierten Trace-Eintrag (alle Failed-Tasks)
- **Erwartet:** Task-Detail öffnet sich, zeigt Timeline, Cost, Result
- **Tatsächlich:** Volle App-Crash-Screen "Something went wrong!" — Recovery nur per Reload
- **Console:** `TypeError: firstTrace.id?.slice is not a function`
- **Betroffen:** Mindestens 16 der 30 Tasks (alle Failed-Tasks)

## 🟠 Major

### M-1 · `/chat` — "+ New conversation" tut nichts

- **Was:** Klick auf den Button öffnet keinen Dialog zur Agenten-Auswahl
- **Erwartet:** Modal oder Inline-Form zur Auswahl eines Agenten + Projekt
- **Tatsächlich:** Keine sichtbare Reaktion, kein Dialog, keine neue Conversation in der Sidebar

### M-2 · `/chat` — Bestehende Conversation heißt "Unknown agent"

- **Was:** Die einzige Conversation in der Sidebar wird als "Unknown agent" angezeigt
- **Erwartet:** Agent-Name (z.B. "office@company") oder Conversation-Titel
- **Tatsächlich:** Agent-ID wird nicht aufgelöst

### M-3 · `/chat` — Conversation-History lädt nicht beim Auswählen

- **Was:** Klick auf "Unknown agent" selektiert die Conversation, zeigt aber weiter "Start a conversation below"
- **Erwartet:** Bisherige Nachrichten werden angezeigt
- **Tatsächlich:** Leerer Chat-Bereich trotz existierender Nachrichten

### M-4 · `/chat` — Plan-Approve-Button bleibt nach Approval hängen

- **Was:** Nach Klick auf "Approve" bleibt der Plan-Proposal-Block dauerhaft im Chat-Fenster
- **Erwartet:** Buttons werden durch Status ("Approved") ersetzt, Agent-Antwort erscheint
- **Tatsächlich:** Block unverändert, "Processing…" bleibt stehen; API gibt 409 zurück
- **Console:** 404 auf `/api/v1/plans/{id}/approve` (mehrfach)

### M-5 · `/memory` — Suche findet keine Ergebnisse für existierende Facts

- **Was:** Suche nach "blog" zeigt "No facts found" obwohl zwei Facts "Blog tone…" und "Blog content pipeline…" existieren
- **Erwartet:** Substring- oder semantische Suche trifft auf "blog"
- **Tatsächlich:** Kein Treffer; Fehlermeldung enthält unverständlichen technischen Hinweis auf Vector-Score
- **Ursache:** Wahrscheinlich kein Vector-Index für SimpleVectorStore oder Score-Threshold zu hoch

## 🟡 Minor

### m-1 · `/overview` — "+ New task" zeigt `window.alert()` Placeholder

- **Was:** Klick öffnet native Browser-Alert mit "⌘K palette coming in M5."
- **Erwartet:** Task-Erstellungs-Dialog oder Command-Palette-Integration
- **Tatsächlich:** `window.alert()` — sieht sehr unfertig aus

### m-2 · `/plans` — Conversation-Link navigiert ohne ID nach `/chat`

- **Was:** "From conversation: a33adf70-…"-Link zeigt auf `/chat` ohne Conversation-ID
- **Erwartet:** Navigiert zu `/chat/{conversationId}` oder öffnet die Conversation direkt
- **Tatsächlich:** Landet auf leerer Chat-Übersicht

### m-3 · `/workflows` — Workflow-Karte nicht klickbar, kein "Run"-Button

- **Was:** Die Workflow-Karte in "AVAILABLE WORKFLOWS" ist nicht interaktiv
- **Erwartet:** Klick öffnet Detail oder triggert Run; Run-Button sichtbar
- **Tatsächlich:** Kein onClick, kein Link — Karte ist rein dekorativ

### m-4 · `/agents` (Skills-Tab) — Skills nur als Plain Text, keine Links

- **Was:** Skills-Tab zeigt Skill-Namen ohne Link oder Detail-Möglichkeit
- **Erwartet:** Klickbare Links zu `/skills/{name}` oder Inline-Detail
- **Tatsächlich:** Nur Text, kein weiterer Kontext

### m-5 · `/tasks` — Timeline-Timestamps, Cost, Duration bei COMPLETE-Tasks alle "—"

- **Was:** Timeline zeigt "Started: —", "Completed: —", Cost = "—", Duration = "—", Tokens 0/0
- **Erwartet:** Tatsächliche Timestamps und Kosten angezeigt
- **Tatsächlich:** Alle numerischen Felder leer trotz COMPLETE-Status

### m-6 · `/traces` — Task-ID-Filter funktioniert nicht mit Short-Hash

- **Was:** Eingabe von Short-Hash (z.B. `76e91e36`) liefert "No traces"
- **Erwartet:** Filter matcht Short-Hash oder Full-UUID
- **Tatsächlich:** Kein Match — Tasks werden überall mit Short-Hash dargestellt, Filter erwartet Full-UUID

### m-7 · `/metrics` — Interne camelCase-Key-Namen im UI sichtbar

- **Was:** Warning-Boxes zeigen `skillSuccessRate: no skill.used events in window`
- **Erwartet:** Nutzerfreundlich: "Keine Daten im Zeitraum" oder keine Box
- **Tatsächlich:** Interne Bezeichner und technische Ereignis-Namen direkt sichtbar

### m-8 · `/health` — "DB connected" zeigt Badge "COMPLETE"

- **Was:** Connection-Status wird mit dem Task-Badge "COMPLETE" dargestellt
- **Erwartet:** Badge "OK" / "Connected" oder grüner Punkt
- **Tatsächlich:** "COMPLETE" ist semantisch falsch für einen Connection-Status

## 🔵 Nice-to-have

### n-1 · `/traces` + `/workflows` — Dev-Kommentare als permanenter UI-Text

- Traces: *"Flat event log, not a tree — nested step-tree would need parent-event linking, not in schema."*
- Workflows: *"Parallel-group nesting simplified — parallel-group rendering requires YAML source, not exposed by REST API."*
- **Empfehlung:** Entfernen oder als Tooltip/Hilfe-Icon verstecken

### n-2 · ⌘K Palette — durchsucht nur Nav-Links, keine Entitäten

- Suche nach "office" findet Agent `office@company` nicht
- **Erwartet:** Palette durchsucht Agenten, Tasks, Workflows, Conversations
- **Tatsächlich:** Nur statische Nav-Links durchsuchbar

### n-3 · `/skills` — Skills aus `pragents.yaml` nicht in Library sichtbar

- Agenten haben Skills ("calendar-management", "task-tracking"), aber Skills-View zeigt 0 aktive Skills
- Technisch korrekt (nicht via DB importiert), aber für Nutzer verwirrend

### n-4 · `/goals` — Goals nicht interaktiv, kein "Run now"-Button

- Goal-Einträge sind pure Tabelle ohne Interaktion
- **Erwartet:** Klick öffnet Detail; "Run now"-Button für manuelle Ausführung

### n-5 · `/costs` — "—" statt "€0.00" bei Null-Verbrauch

- "This month" und "Total calls" zeigen "—" bei Wert 0
- **Erwartet:** "€0.00" / "0" — Dash suggeriert Ladefehler statt keinen Verbrauch

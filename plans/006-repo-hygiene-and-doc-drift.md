## Why this matters

Several small, independently-safe hygiene items that reduce confusion and
maintenance drag:

- The root `package.json` declares `vectordb@^0.21.2` (the deprecated legacy
  LanceDB wrapper) but nothing imports it — only `@lancedb/lancedb` (in the server
  workspace) is used. Dead dependency = wasted install, extra audit noise.
- `@hono/node-ws` is declared in **both** root (`^1.3.1`) and server (`^1.0.0`)
  with divergent ranges — unclear ownership; workspace resolution picks one and
  the other is misleading.
- `web/prototype.html` is a tracked v3-dashboard reference artifact (see
  `git log`: "add prototype.html for v3 dashboard reference") that no longer
  serves a purpose in the shipped app.
- `AGENTS.md` claims parallel workflow groups are "Promise.allSettled with
  fail-fast" — the engine actually implements a **configurable** failure policy
  (`abort` / `continue` / `resume-later`), and `allSettled` never fails fast. The
  doc misleads anyone reasoning about workflow error behavior.
- `README.md` points the dashboard at `localhost:5173`, but `web/vite.config.ts`
  sets `port: 5174` — new users hit connection-refused.

None of these change runtime behavior; each removes a small, real source of
confusion.

## Steps

### Step 1: Confirm `vectordb` is unused, then remove it

Run `grep -rn "vectordb" server web packages --include="*.ts"`. If it returns
**any** import/require, STOP (the assumption is wrong). If empty, remove the
`"vectordb": "^0.21.2"` line from the root `package.json` `dependencies`.

**Verify**: `grep -n "vectordb" package.json` → no matches.

### Step 2: Resolve the `@hono/node-ws` version duplication

Decide a single owner. The server is what uses it at runtime, so keep it in
`server/package.json` and remove it from the root `dependencies` — **unless** the
root declaration is load-bearing for the WS wiring in `server/src/index.ts`
(check whether `@hono/node-ws` is imported from server code; it is). Set the
server range to the same value the root used (`^1.3.1`, the newer one) so no
downgrade occurs, and delete the root entry.

If you are unsure whether removing the root entry breaks workspace hoisting, the
safe alternative is to align **both** to `^1.3.1` and leave both entries — that
also removes the drift. Either is acceptable; note which you chose in the commit.

**Verify**: `npm install` → exit 0. `cd server && npx tsc --noEmit` → exit 0.

### Step 3: Delete the prototype file

Delete `web/prototype.html`.

**Verify**: `test ! -f web/prototype.html && echo gone` → prints `gone`.
`cd web && npm run build` → exit 0 (build does not reference it).

### Step 4: Fix the AGENTS.md workflow wording

In `AGENTS.md`, change the parallel-groups description from "Promise.allSettled
with fail-fast" to describe the real behavior. Suggested replacement:

> **Parallel step groups** via `Promise.allSettled`, with a configurable failure
> policy (`onStepFailure`: `abort` throws and stops the run, `continue` collects
> partial results into `<step.id>.results`, `resume-later` is currently treated as
> `continue` pending full implementation).

**Verify**: `grep -n "fail-fast" AGENTS.md` → no matches (or only in unrelated
contexts you did not touch).

### Step 5: Fix the README dashboard port

In `README.md`, change the dashboard URL from `localhost:5173` to `localhost:5174`
to match `web/vite.config.ts`.

**Verify**: `grep -n "5173" README.md` → no matches. `grep -n "5174" README.md`
→ shows the corrected line.

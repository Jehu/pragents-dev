## Findings considered and rejected

Recorded so they are not re-audited next run:

- **`server/dist/` committed to git** (suggested by an audit pass): rejected —
  `git ls-files server/dist` returns nothing; the compiled output is not tracked.
- **SQL injection in `/api/v1/traces` via `taskId`** (`server/src/index.ts` traces
  route): rejected — the query is parameterized (`task_id = ?` and `LIKE ?`); no
  string concatenation of user input. The 8-char-minimum prefix rule is an
  intentional guard, not a vulnerability.
- **`env:VAR` config resolution allows YAML injection** (`config/loader.ts`):
  rejected as a practical finding — `pragents.yaml` and the referenced env vars
  are operator-controlled; the resolved value is substituted as a scalar, not
  re-parsed as YAML. Not worth a plan.
- **Human-gate approval lacks project-ownership check** (IDOR framing,
  `gates.ts` / `tool-executor.ts` `approve_gate`): downgraded, not planned. The
  product is single-operator local-first, so cross-tenant IDOR does not apply.
  The real question — *should LLM-driven agents be able to approve human gates at
  all?* — is a design decision for the maintainer (it partly defeats human-in-the-
  loop), not a code bug. Flagged in the review summary as a direction item.
- **LanceDB silent fallback to SimpleVectorStore** (`memory/engine.ts`): rejected
  as a bug — the engine already exposes `isDegraded()` and `storeName()` and logs
  a warn on fallback. (The *separate* swallowed `vectorStore.add` catch is real
  and is covered by plan 005.)
- **`TaskTracker` instantiated per `pmCheck`** (`goals/scheduler.ts`): noted but
  not planned — SQLite serializes writes, so it is a micro-inefficiency, not a
  correctness issue. Fold into a future scheduler cleanup if one is opened.
- **`server/src/index.ts` god-module refactor** (519 lines): real tech debt, but
  L-effort and HIGH-risk (startup critical path) with no functional payoff on its
  own. Deferred until it actively blocks a feature; not worth the risk now.
- **ESLint/Prettier introduction**: worthwhile DX, but deliberately not planned
  here — it is a taste/config decision better made by the maintainer, and a
  repo-wide format churn would bury the higher-value diffs above. Revisit after
  002 lands CI.

## Broader direction items (for the maintainer, not bugs)

These were options surfaced by the review. All three have now been turned into
concrete plans (008–010) at the maintainer's request:

- **Agent trust boundary for gate approval / memory writes** → **plan 008**
  (per-agent `tools: { allow, deny }` policy, deny-by-default capable, enforced at
  the single `ToolExecutor.execute` choke point; backward compatible).
- **Complete or remove `resume-later`** → **plan 009**. Recommendation: **remove**
  the stub — it silently behaves as `continue`, a faithful implementation needs
  durable resumable run state the engine lacks, and the capability is already
  expressible via an explicit `human_gate` step. Plan 009 executes removal and
  documents the "finish it" alternative if the maintainer prefers to build it.
- **WebSocket auth for browsers** → **plan 010** (short-lived, single-use WS
  ticket minted by an authenticated `POST /api/v1/ws-ticket`, connected via
  `?ticket=`; the long-lived token never travels in a URL). Depends on 003.
